Sobre o Time

QA como pilar estratégico do produto

O time de QA da BIUD atua de forma integrada ao desenvolvimento, garantindo qualidade desde a concepção até a entrega em produção. Não somos um gargalo — somos um acelerador de confiança.

O Portal de QA da BIUD centraliza todos os processos, padrões e ferramentas que garantem a excelência das nossas entregas — desde as definições de pronto (DoR / DoD) até os templates de abertura de bugs, regras de negócio e modelos de execução de teste.

Atuamos de forma integrada ao desenvolvimento no projeto BIUD V3 – ESG SEBRAE, cobrindo desde o refinamento do backlog até o pós-deploy: testes manuais, automação, análise de causa raiz (RCA), KPIs de qualidade, severidade/prioridade de bugs e observabilidade.

📖 Glossário Técnico

QA
Quality Assurance — Garantia de Qualidade
Processo de verificação sistemática que garante que o produto atende aos requisitos e padrões definidos antes de chegar ao usuário final. O QA atua em todo o ciclo de desenvolvimento, não apenas no final.
DoR
Definition of Ready — Definição de Pronto (para entrar no sprint)
Conjunto de critérios que um card (tarefa) deve atender antes de ser aceito em uma sprint. Exemplo: ter descrição clara, critérios de aceite, design aprovado e sem dependências bloqueantes.
DoD
Definition of Done — Definição de Concluído
Critérios que uma funcionalidade deve cumprir para ser considerada "pronta" e entregável. Inclui: código revisado, testes passando, documentação atualizada e aprovação do QA.
RCA
Root Cause Analysis — Análise de Causa Raiz
Processo estruturado para identificar a causa fundamental de um incidente ou bug, não apenas o sintoma. O objetivo é corrigir a origem do problema para evitar recorrência, não apenas o efeito visível.
CI/CD
Continuous Integration / Continuous Deployment
Pipeline automatizado que integra código continuamente (CI) e faz deploy em ambientes de forma automática (CD). No contexto do QA, os testes automatizados são executados no CI para bloquear deploys com falhas.
KPI
Key Performance Indicator — Indicador-Chave de Desempenho
Métricas quantificáveis usadas para medir o desempenho de um processo ou área. No QA, exemplos são: número de bugs por sprint, taxa de regressão, cobertura de testes e tempo médio de resolução.
HMG
Homologação — Ambiente de Homologação
Ambiente de testes que replica a produção para validação de funcionalidades antes do deploy real. No projeto ESG Sebrae, o HMG é acessado em esg-hmg.sebrae.com.br. "Equalizar o HMG" significa sincronizá-lo com o estado atual de produção.
ESG
Environmental, Social and Governance
Conjunto de critérios ambientais, sociais e de governança usados para avaliar empresas. O projeto BIUD V3 – ESG SEBRAE é uma plataforma que auxilia pequenas empresas a medir e melhorar seus indicadores ESG.
MIA
Assistente Virtual Inteligente da BIUD
Assistente de IA integrado ao produto ESG Sebrae que auxilia os usuários na plataforma com respostas contextuais e orientações sobre o questionário de diagnóstico ESG.
Playwright
Framework de automação de testes end-to-end
Ferramenta open-source da Microsoft para automação de testes de interface (UI) em navegadores. Suporta Chromium, Firefox e WebKit. No QA da BIUD é usado com TypeScript e padrão Page Object Model (POM).
Smoke Test
Teste de Fumaça — validação básica de sanidade
Suite de testes rápidos (idealmente abaixo de 10 minutos) que verifica se as funcionalidades críticas do sistema estão operacionais. É executado após cada deploy para detectar falhas graves antes de testes mais completos.
Sprint
Iteração de desenvolvimento (metodologia Scrum/Ágil)
Ciclo de trabalho de duração fixa (geralmente 2 semanas) onde o time desenvolve e entrega um conjunto de funcionalidades planejadas. O QA da BIUD está na Sprint 39 desde 25/05/2026.
API
Application Programming Interface
Interface que permite a comunicação entre sistemas. No projeto ESG Sebrae, o QA valida as APIs de Core, Payment, ESG, Clients, Insights e MIA nos ambientes de HMG e produção.
UI
User Interface — Interface do Usuário
A camada visual do produto com a qual o usuário interage diretamente no navegador. Testes de UI validam fluxos de interação — cliques, formulários, navegação — simulando o comportamento real do usuário.
Bug / Sub-Bug
Defeito no software
Bug é um defeito que causa comportamento incorreto no sistema. Sub-bug é um defeito derivado ou relacionado a um bug principal. No Jira, sub-bugs são cards filhos vinculados ao bug pai para rastreamento granular.
MEI / ME / EPP
Microempreendedor Individual / Microempresa / Empresa de Pequeno Porte
Classificações do porte de empresas no Brasil. No contexto do ESG Sebrae, o porte (CPE) determina quais questionários e planos a empresa pode acessar na plataforma.
POM
Page Object Model — Padrão de Projeto para Automação
Padrão de arquitetura de testes onde cada página ou componente do sistema possui uma classe correspondente que encapsula seus seletores e ações. Melhora a manutenibilidade e reutilização do código de testes.
BIUD Talks
Programa interno de disseminação de conhecimento
